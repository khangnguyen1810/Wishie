# AC 8: Tutorial Overlay Renders Above Content Without Disrupting Navigation

- [ ] **Scenario: Tutorial overlay does not block sheet, full-screen cover, or dialog presentations** ❌ FAILED
  - Given: User "user-ac8-overlay-layer" is on `HomeView` with the tutorial overlay visible
  - When: A sheet, full-screen cover, or dialog is triggered from within `HomeView`
  - Then: The modal presentation renders above the tutorial overlay and behaves normally
  - Verify: `.sheet`, `.fullScreenCover`, and dialog modifiers function correctly while the tutorial is visible; the navigation stack is not disrupted
  - **Failure**: The custom dialog modifiers (`showDialogIfNeeded`, `showFullScreenDialog`) render BELOW the tutorial overlay, not above it. The scenario requires all modal presentations to render above the tutorial overlay, but only UIKit system-level presentations (`.sheet`, `.fullScreenCover`) satisfy this. Custom overlay-based dialogs do not.
  - **Root Cause**: In `HomeView.swift`, the modifier chain applies the tutorial overlay as the LAST (outermost) modifier, after all `showDialogIfNeeded` and `showFullScreenDialog` calls. SwiftUI renders each successive `.overlay` on top of the previous one, so the tutorial overlay (applied last) is drawn on top of all custom dialog overlays. Specifically: `showDialogIfNeeded` and `showFullScreenDialog` are both implemented as `.overlay {}` inside `DialogView.swift` (lines 119-139), and they are chained BEFORE the tutorial overlay in `HomeView.swift` (lines 250-260 vs. 261-266). When `$homeViewModel.isGettingList` is `true` during the initial wishlist fetch on first launch — the exact moment the tutorial is also showing — the full-screen loading overlay is completely covered by the tutorial overlay's `Color.black.opacity(0.65).ignoresSafeArea()` background.
  - **Affected Files**:
    - [Wishie/Screens/Home/HomeView.swift](Wishie/Screens/Home/HomeView.swift#L224-L266) — modifier ordering: `.showDialogIfNeeded` × 3 and `.showFullScreenDialog` applied before `.overlay { HomeTutorialOverlayView }`
    - [Wishie/CustomView/DialogView.swift](Wishie/CustomView/DialogView.swift#L119-L139) — `showDialogIfNeeded` and `showFullScreenDialog` are `.overlay {}`-based, not system presentations
  - **Failure**: `.sheet` and `.fullScreenCover` correctly render above the tutorial (UIKit system-level presentations), but the custom dialog modifiers (`.showDialogIfNeeded`, `.showFullScreenDialog`) do NOT render above the tutorial — they are visually obscured by it.
  - **Root Cause**: In SwiftUI, `view.overlay(A).overlay(B)` causes B to render on top of A. The tutorial `.overlay` is the last modifier in `HomeView`'s modifier chain (applied after `.showDialogIfNeeded` and `.showFullScreenDialog`). Since both `showDialogIfNeeded` and `showFullScreenDialog` internally expand to `.overlay { ... }` (confirmed in `DialogView.swift`), the tutorial overlay stacks above them. `HomeTutorialOverlayView` renders `Color.black.opacity(0.65).ignoresSafeArea()` as a full-screen background, completely obscuring any dialog overlay beneath it. A concrete failure path: on first launch, `HomeView`'s `.task` triggers `homeViewModel.getListWishlist()`, which likely sets `isGettingList = true`, activating `showFullScreenDialog` — simultaneously `hasSeenHomeTutorial` is `false`, so the tutorial is also active; the tutorial's dark overlay covers the loading indicator entirely.
  - **Affected Files**:
    - `Wishie/Screens/Home/HomeView.swift` — `.overlay { HomeTutorialOverlayView }` is the last modifier, placed after `.showFullScreenDialog($homeViewModel.isGettingList)` and all `.showDialogIfNeeded(...)` calls
    - `Wishie/CustomView/DialogView.swift` — `showDialogIfNeeded` and `showFullScreenDialog` both use `self.overlay { ... }` internally (lines ~113–138)
